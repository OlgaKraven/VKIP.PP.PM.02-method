    Этап 4. Оформление отчёта по практике¶

    Задание¶

    На данном этапе необходимо:

    1. Подготовить итоговый отчёт по практике на основе шаблона.
    2. Включить в отчёт результаты этапов 1–3, конфигурационные файлы, скриншоты, дампы и сводные таблицы.
    3. Оформить вариативную часть (по индивидуальной предметной области).
    4. Сформировать репозиторий с конфигами и скриптами и приложить ссылку.
    5. Подготовиться к защите.

    Шаблон отчёта¶

    Заготовка отчёта в формате Markdown: assets/templates/Отчёт_по_практике_ПМ02.md

    Шаблон содержит:

    • титульную страницу;
    • содержание;
    • введение;
    • 4 этапа с подразделами и таблицами;
    • разделы для конфигов, скриншотов и дампов;
    • выводы по каждому этапу;
    • заключение и список источников;
    • таблицу ссылок на репозитории и материалы.

    Текст в [ КВАДРАТНЫХ СКОБКАХ ] нужно заменить своими данными; блоки 📌 ... — это инструкции для студента, в финальном отчёте удаляются.

    Конвертация в DOCX/ODT¶

    Markdown-шаблон легко конвертируется через Pandoc:

    pandoc "Отчёт_по_практике_ПМ02.md" \
       -o "Отчёт_по_практике_ПМ02.docx" \
       --reference-doc=reference.docx     # опционально, фирменный стиль

    Альтернатива — открыть шаблон в Typora / Obsidian / Marktext и экспортировать в DOCX.

    Что должно быть в отчёте по каждому этапу¶

    Этап Обязательное содержание
    1 имя/версия СУБД, параметры подключения, дамп БД, ACL по матрице, скриншоты, описание ВМ, точка восстановления
    2 конфиги сети, правила МЭ, правки pg_hba.conf, результаты nmap снаружи, парольные политики, журнал входов
    3 экспорт журналов событий, анализ автозагрузки, отчёт антивируса, метрики CPU/RAM/диска/сети, скриншоты внешнего мониторинга, таблица проблем и рекомендаций
    4 оформленный документ, репозиторий, готовность к защите

    Индивидуальная часть¶

    Индивидуальная часть формируется образовательной организацией. Содержание определяется требованиями работодателя / спецификой стенда варианта.

    Рекомендованная структура индивидуальной части практики:

    1. Описание предметной области (см. список вариантов) и её требований к ИКС.
    2. Состав стенда варианта — какие сервисы дополнительно поднимаются (1С, Битрикс24, Moodle, iiko, СКУД, IP-телефония и т.д.).
    3. Расширенная настройка:
      • SSO/AD/LDAP (если применимо);
      • резервное копирование по расписанию;
      • публикация веб-интерфейса по HTTPS;
      • VLAN / VPN до удалённого офиса.
    4. Долгосрочный мониторинг и алертинг: триггеры в Zabbix / правила Alertmanager / уведомления в почту/Telegram.
    5. Аудит ИБ по чек-листу варианта, сводная таблица рекомендаций.
    6. Отчёт о выполненной работе — отдельный раздел в общем документе.

    Репозиторий студента¶

    Создайте свой публичный/приватный репозиторий со всеми конфигами и скриптами:

    mkdir VKIP.PP.PM.02-stand-42
cd VKIP.PP.PM.02-stand-42
git init
mkdir -p configs scripts dumps screenshots
# скопируйте сюда финальные конфиги, дампы, скрипты, скриншоты
git add .
git commit -m "init: stand for variant 42"
git remote add origin git@github.com:<user>/VKIP.PP.PM.02-stand-42.git
git push -u origin main

    В отчёт — таблица ссылок:

    № Артефакт Ссылка
    1 Методичка по практике https://github.com/OlgaKraven/VKIP.PP.PM.02-method
    2 Стенд студента https://github.com//VKIP.PP.PM.02-stand-42
    3 Дамп БД dumps/corpdata_42.sql
    4 Скриншоты папка screenshots/

    Защита практики¶

    К защите необходимо подготовить:

    1. печатный или электронный экземпляр отчёта;
    2. демонстрацию рабочего стенда (ВМ запущена, сервисы работают);
    3. готовность ответить на вопросы по 4 этапам;
    4. чек-лист самопроверки.

    Чек-лист самопроверки перед защитой¶

    Вопрос Да/нет
    Стенд можно поднять с нуля по записям из отчёта?
    Все упомянутые конфиги приложены целиком?
    Скриншоты подписаны и пронумерованы?
    В таблице прав указано, что и почему разрешено/запрещено?
    По каждому этапу есть вывод (3–5 предложений)?
    Есть итоговое заключение с ответом на цель практики?
    Список источников оформлен по ГОСТ?
    В тексте нет паролей/секретов в открытом виде?

    Чек-лист этапа 4¶

    Вопрос ПК Да/нет Комментарий
    Шаблон заполнен полностью? —
    Все этапы 1–3 отражены в отчёте? 2.1–2.4
    Конфиги, скриншоты и дампы приложены? 2.1, 2.2
    Сформирован репозиторий студента? —
    Подготовлена демонстрация стенда? 2.2, 2.4
    Документ конвертирован в .docx/.odt? —

    Что сдаётся преподавателю¶

    1. Отчёт_по_практике_ПМ02.docx (или .odt).
    2. Папка report/ (см. структуру выше) — может быть отдельным архивом или репозиторием.
    3. Ссылка на личный репозиторий студента.
    4. Готовность к защите по графику.
